# Audit du projet — 21 septembre 2026

Version du dépôt **2.0.4**, pour l'installation Profilarr 2.2 déclarée par l'utilisateur. Cet audit porte sur le dépôt compilé et ses règles, **pas sur l'état actuellement appliqué sur Nexus**.

## Pourquoi le problème avait échappé aux contrôles

L'ordre des qualités a été réparé en 2.0.3. Deux anciens contrôles statiques étaient trompeurs : l'un pouvait lire le cutoff d'un autre profil, l'autre ne trouvait plus les profils après changement d'incrément. Leur remplacement par une lecture du SQL compilé est conservé.

L'audit étendu a aussi établi que le pipeline sélectionnait seulement **74 des 519 cas** annoncés. Son simulateur Python ne reproduisait pas les regex .NET, le groupe de release réellement analysé, ni le regroupement des conditions par type ; il ignorait certaines conditions. Un passage au vert ne prouvait donc pas la cohérence de toute la base.

La suite exécute maintenant tous les cas avec les métadonnées et regex du parser Profilarr .NET. La combinaison des conditions est testée par type : toutes les conditions obligatoires et au moins une condition du groupe doivent réussir. Référence : [SpecificationMatchesGroup Radarr](https://github.com/Radarr/Radarr/blob/develop/src/NzbDrone.Core/CustomFormats/SpecificationMatchesGroup.cs). Les bornes des CF taille suivent [SizeSpecification](https://github.com/Radarr/Radarr/blob/develop/src/NzbDrone.Core/CustomFormats/Specifications/SizeSpecification.cs) : minimum exclusif, maximum inclusif.

## Corrections confirmées

| Défaut | Correction et protection |
|---|---|
| HDTV-2160p conservait des plafonds génériques énormes | Plafonds compacts **250 / 150 / 120 Mo/min** pour Films / Séries / Anime, vérifiés avec les autres qualités |
| Smart Replace Sonarr stocké en texte | Valeur numérique **4**, selon la conversion Profilarr ; renommage toujours désactivé |
| `FRENCH.SUBS` valorisé comme doublage | Classé sous-titres FR, plus VFF ; contrôle aussi avec préfixe MULTI |
| `MULTI.VF` restait ambigu | Palier MULTI-VFF, cohérent avec VF générique déjà admis ; aucun cumul avec le palier ambigu |
| Full Disc exclu à tort dès que le titre contenait AVC | Exclusion dédiée aux encodes x264 explicites, sans neutraliser les disques AVC ; WEB/Remux/encodes restent distincts |
| Attentes de tests incohérentes | **120 attentes** corrigées selon la signification des formats et les exclusions documentées : AAC ≠ FLAC, SDR ≠ HDR, mono ≠ MULTI, IMAX Enhanced ≠ double bonus IMAX… Aucun score modifié pour satisfaire les tests |
| Documentation divergente | 7.1 à −800, CA seul non reconnu, VOQ = VFQ, couverture réellement exécutée explicitée |

Les **519 cas historiques sont conservés**, avec neuf cas complémentaires : **528 au total**. Les corrections d'attentes ne sont pas un contournement des défauts de détection : les cas négatifs FRENCH.SUBS et les cas positifs MULTI.VF/disques AVC ont été maintenus et ont conduit aux corrections fonctionnelles.

## Résultats et reproductibilité

- Compilation schema 1.1.0 + toutes les opérations SQL, dix profils, 22 groupes / 87 membres : OK.
- Trois presets media, **74 définitions**, naming, réglages media et deux délais : OK.
- **528/528** cas CF, aucun cas ignoré avec le parser disponible.
- **44/44** cas complémentaires : codecs/éditions sans ancienne fixture, packs de saison et bornes de taille (minimum exclu, maximum inclus). Les **78 CF** disposent désormais d'au moins un cas positif ; une perte de couverture fait échouer la suite.
- **149/149** assertions sur dix profils : 87 scénarios synthétiques et les douze simulations `ops/12`.
- **91/91** configurations volontairement corrompues rejetées : ordre, cutoff, activation, seuils, membres, tailles et naming. Injections uniquement dans une base temporaire.
- Régression HEVC dédiée, cohérence documentaire et liens : inclus dans la commande de validation.

Commande complète : `PARSER_URL=http://127.0.0.1:15000 python3 scripts/validate.py` avec un parser Profilarr démarré à cette adresse. Le contrôle local a utilisé le parser compilé depuis [Profilarr 4b87791](https://github.com/Dictionarry-Hub/profilarr/tree/4b877913c50ff2964f179255c6bf2f517920a123/src/services/parser). La CI utilise le service parser déclaré dans son workflow. Sans parser, le succès local est explicitement **partiel** ; en CI son absence échoue.

## Limites et application

Ces contrôles ne font pas tourner le moteur d'import complet de Radarr/Sonarr et ne garantissent pas l'absence de tout bug. Ils ne vérifient pas les fichiers réellement présents, les réglages locaux écrasant la base, les limites des indexeurs ni la réussite de Sync sur Nexus. Les anciens titres Torr9 restent des régressions historiques ; les trackers actuels déclarés sont C411, Gemini Tracker et TR4ker.

Après réception de cette version : **Pull → Compile → Sync**, avec **Media Management** pour les plafonds et le naming. Dans Radarr/Sonarr, contrôler que le profil appliqué au média a bien sa résolution cible en haut. Vérifier ensuite une amélioration d'un fichier 720p vers 1080p/2160p ; une mise à jour GitHub seule ne prouve pas que ces paramètres ont été appliqués.
